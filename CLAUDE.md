# SkillCraft: notes for Claude

SkillCraft is an OSRS-inspired RPG mod for Minecraft Java. The owner, Todd, is new to modding: explain what you change in plain words and keep the docs up to date.

## Stack
- **Game and loader:** Minecraft **26.2**, NeoForge **26.2.0.88**, ModDevGradle, **Java 25**.
- **Dev machine:** Windows with Git Bash. **There is no Python**, so write generator scripts as single-file Java programs (`java scripts/foo/Bar.java`) or Bash.
- **Writing files:** use your file tools rather than shell heredocs that contain apostrophes.

## Commands
| What | Command |
|---|---|
| Compile and package | `./gradlew build` (jar in `build/libs/`) |
| Play | `./gradlew runClient`. With `-Pworld="New World"` it loads straight into that save. |
| GameTests (headless) | `./gradlew runGameTestServer`. It must end with `All N required tests passed :)`. |
| Dedicated server | `./gradlew runServer` (accept `run/eula.txt` once) |
| Ability HUD/Book screenshots | `./gradlew runClient -Pshowcase=abilities -Pworld=<save>` |
| Fishing & Cooking screenshots | `./gradlew runClient -Pshowcase=fishing -Pworld="Showcase World"`. This digs a pond next to the player, so use a copy of a save rather than Todd's "New World". |
| Boss screenshot showcase | `./gradlew runClient -Pshowcase -Pworld=<save>`. Writes `run/screenshots/showcase_*.png`, then quits. `runServer -Pshowcase` creates a world and stops. See `dev/Showcase`. |

- **In-game:** **K** opens the Skills screen and **V** cycles the attack style.
- **Admin command:** `/skill get|set|addxp|reset <player> <skill> <value>`.
- **Reloading:** after editing assets (textures, models, animations, lang) press **F3+T**. After editing data (data maps, loot tables, recipes, tags) run `/reload`. Java changes need a restart.

## CI (GitHub Actions)
- **Build** (`.github/workflows/build.yml`): `./gradlew build`, then `runGameTestServer`. It prints the `[loot_rates]` lines and warns on SkillCraft WARN/ERROR lines in the server log.
- **Client smoke** (`client-smoke.yml`, **manual only**: Actions tab → Run workflow): starts the real client under Xvfb with software OpenGL, using `scripts/ci/client_smoke.sh`. Running the showcase locally is faster.
  - It loads a flat world and runs a showcase scene. The workflow's `scene` input picks it: empty for the boss, or `builds` or `abilities`.
  - The showcase clicks through world-open prompts such as the "backup / I know what I'm doing" screen. An early run stalled on one of them. With that fixed, the abilities scene takes about 3 minutes.
  - It fails on a crash or missing screenshots, and lists model, texture and animation warnings.
  - The screenshots are uploaded as the `client-smoke` artifact.
- Keep Build green on every push.

## Where things are
- **Code layout:** see `README.md` ("Project layout").
- **Design docs:** `docs/DESIGN.md` (the whole design and roadmap), `docs/COMBAT.md` (combat rules and numbers), `docs/BOSS_SLAGHEART.md` (the first boss, with its verified numbers).
- **Data-driven tuning:** `src/main/resources/data/skillcraft/data_maps/`.
  - `item/skill_requirements.json`: level gates
  - `item/weapon_styles.json`, `item/armor_defences.json`, `entity_type/combat_profiles.json`: damage types, typed defence, mob weaknesses
  - `entity_type/boss_tuning.json`: boss stats
  - `item/bench_recipes.json`: generated by `scripts/gen_bench_recipes.sh`
  - `item/gathering_tools.json`: axe, pickaxe and fishing rod tier/power
  - `item/smelting.json`, `item/cooking.json`: Smelter and Cooking Range recipes (cooking has a burn curve)
  - `block/elemental_hearts.json`, `item/elemental_hearts.json`: Elemental Heart drop chances from vanilla logs and ores, and from vanilla rod catches
- **Nodes and fishing spots:** stats per type in `node/NodeType.java`. Fishing types (`isSpot()`) are entities on water (`fishing/FishingSpotEntity`) placed from shoal items, not blocks; the water rules are in `fishing/FishingWater`.
- **Elemental Hearts:** nodes are attuned from one heart (`node/ElementalHeartItem`, one item tinted per node), not from resources. Hearts drop in `node/HeartEvents`; player-placed blocks are tracked per chunk (`node/PlacedResources`) so they never drop one. See DESIGN.md "Elemental Hearts".
- **XP curve:** `skill/XpTable` is the OSRS curve ×0.75 (`CURVE_SCALE`); 99 = 9,775,823.
- **Leycraft** (`leycraft/`, `docs/LEYCRAFT.md`): Ley Shards from the Ley Stone node are woven into motes at a Ley Altar. The element comes from the surroundings (`Resonance`).
  - Data maps: `block/ley_resonance.json`, `item/ley_essence.json`, `item/ley_weaves.json`. Biome tags: `ley_resonance/<element>`.
  - Weave numbers (radius, biome and weather bonuses, careful-weave multipliers) are server config.
  - The Ley Tuner (`LeyTuning`) finds the nearest strong source of an element. It scans only loaded chunk sections, using the palette check `maybeHas` to skip most of them, and falls back to `findClosestBiome3d`.
  - Careful weaves use the `STEADY_THE_CURRENT` minigame through `LeyWeaving`, with the same seeded replay as attunement. `Minigames.ReplayResult` carries the miss count.
- **Beastbonding** (`bonding/`, `docs/BEASTBONDING.md`): creatures are bonded into a per-player `BondCodex` attachment (not the book item), then summoned and stored by `BondService`.
  - Per-creature numbers: `data_maps/entity_type/bondable.json` (level, mount/companion, tamed or offering, tribute, rekindle time, XP, `summon_as`).
  - Live summons carry `skillcraft_bond_owner`/`skillcraft_bond_id` in their persistent data. `BondEvents` removes any loaded copy the owner's codex doesn't list as Out, and stores summons on logout and dimension change.
  - Changed creatures: `Cliffstrider` (spider subclass, vanilla spider renderer), and follow/fetch goals added to bonded foxes and golems on join. The Cloudray has its own model (`client/bonding/CloudrayModel`), whose texOffs must match `scripts/textures/GenCloudrayTexture.java`.
- **Agility, Magic and Prayer:** design and numbers in `docs/AGILITY_MAGIC_PRAYER.md`.
  - Foci: `item/magic_focus.json`. Offerings: `item/prayer_offerings.json`.
  - Spells, blessings and movement abilities are ability JSON (categories `spell`, `prayer`, `agility`).
  - Faith, shrine and parkour numbers are server config.
- **Combat abilities:** one JSON per ability in `data/skillcraft/skillcraft/ability/`; behaviours in `ability/behavior/`; spec and decisions in `docs/ABILITIES_SPEC.md` (§8). Global ability numbers (Momentum gain, GCD, combat window) live in the server config.
- **Boss animations:** `assets/skillcraft/neoforge/animations/entity/slagheart/*.json`. These are vanilla keyframe JSON read by NeoForge's `AnimationLoader`. Bone names must match `client/boss/SlagheartModel`.
- **Textures:** generated by `scripts/textures/*.java`. Re-run a generator after changing it. The Slagheart generator's cube table must match the model's `texOffs`/box sizes.

## Ground rules
- **IP:** original names, art, text and lore only. Never copy Jagex/OSRS names, wiki text or art. OSRS is a reference for mechanics only.
- **Server-authoritative and multiplayer-safe.** The client only draws.
- **Data-driven where reasonable:** numbers belong in data maps or JSON, not hard-coded.
- **Gear comes only from players.**
  - Station-made gear is stamped `skillcraft:crafted_by`; boss uniques are stamped `skillcraft:earned_by`.
  - Loot, villagers and mobs never hand out unstamped gear or ingots (`loot/CraftedGear`).
  - Consumables (sigil, arrows) are exempt through the `skillcraft:consumables` item tag.
- **Code style:**
  - Short top-of-file comments that say *why*.
  - Registries live in `registry/`.
  - Every player-facing string gets a lang key in `assets/skillcraft/lang/en_us.json`.
- **Docs:** record design decisions in the docs instead of asking, unless something is truly blocking.
- **Commits:** describe the change. Work on a branch and open a PR. Don't merge without Todd.

## GameTests (`gametest/`)
- **Registering a test:** add the function to `ModGameTests.TEST_FUNCTIONS` and a `test(event, name, maxTicks)` line. Each test gets its own environment, so tests run in separate batches. Structure: `skillcraft:test_floor`, a 16×8×16 stone floor.
- **Mock players:** `helper.makeMockServerPlayerInLevel()` is **always creative**, even after `setGameMode`. For survival behaviour (XP, damage) use `FakePlayerFactory.get(level, new GameProfile(uuid, name))`.
- **Dimensions:** the GameTest server only creates vanilla dimensions. Arena tests use the Nether as a stand-in (`ArenaDimension.useStandInForTests`). A real server does load `skillcraft:arena`.
- **Fake players are never ticked.**
  - Call `AbilityService.tick` and tick effects yourself (see `AbilityTests.tickEffects`).
  - Held-weapon attributes aren't applied automatically; use `AbilityTests.hold`.
  - Their teleports are ignored, so also call `setPos`.
  - They can't be hurt, because their client never "loads". Post the damage event directly instead.
  - Set `setYHeadRot` as well as the yaw, because abilities aim with the head.
- **Mock players can't receive custom payloads.** Always send through `ModNetwork.sendTo`, which checks `connection.hasChannel`.
- **Phase 7 tests** (`Phase7Tests`):
  - `magic_bolt` and `magic_spells` use pigs and iron golems as targets, because skeletons burn in daylight and zombies have armour.
  - `agility` drives `AgilityTracker.tick` with `setPos` and `setOnGround`.
  - `prayer` checks blessing maths through `PrayerEvents.damageMultiplier`.
- **DPS harness:** `ability_dps` runs a 60 s simulation. The first build targeted ×1.15–1.25; after the playtest pacing pass it sits at about ×1.39 (the test allows ×1.05–1.55; see ABILITIES_SPEC §8.8).
- **Fishing and cooking:** `FishingTests.pond(...)` builds a stone-rimmed pond for water tests. Drive fishing with `FishingSessions.tick(player)` (fake players aren't ticked). `fishing_session` waits for the 20 s cod resurface.
- **Hearts and XP curve** (`HeartTests`): `xp_curve` pins 99 = 9,775,823 and the doubling every 7 levels; `elemental_hearts` posts `BlockDropsEvent` directly (2,000 diamond-ore breaks) to check the rate and the placed-block rule.
- **Leycraft** (`LeycraftTests`): `ley_resonance` places magma, ice and lightning rods; `ley_weaving` checks exact yields through `quickWeave`/`completeCareful` (call those directly; fake players can't play the minigame); `steady_the_current` wins the minigame with an autopilot and checks the server replay agrees; `ley_tuner` checks the source search and compass directions from the centre of its area (neighbouring test areas may hold leftover blocks).
- **Beastbonding** (`BondingTests`): fake players aren't in the server's player list, so owner lookups by id find nobody. Call `BondService.fallen` directly (the death event can't find the owner), and `BondService.resetSummonCooldown` between summons in one tick.
- **Loot balance:** `LootRateTests` rolls the boss table 20,000 times. It fails if the unique rate, the sigil rate or the per-kill value (6.5–9 gathering-minutes) drifts.

## NeoForge 26.2 API notes (checked against the real classes)
**Read the real sources before using an API.**
- **Minecraft sources:** `build/moddev/artifacts/minecraft-patched-26.2.0.88-sources.jar` (after one build).
- **NeoForge sources:** `neoforge-26.2.0.88-sources.jar` in the Gradle cache.
- **Extracting them:** use `jar xf`. `unzip` silently extracts nothing from these jars.

**Renames**
- `ResourceLocation` → `Identifier`; `GuiGraphics` → `GuiGraphicsExtractor`.
- Screens: `render`/`renderBg`/`renderLabels` → `extractRenderState`/`extractBackground`/`extractLabels`.
- `minecraft.setScreen` → `minecraft.gui.setScreen`, and the current screen is `minecraft.gui.screen()`.
- `level.random` is protected, so use `getRandom()`. `BlockPos.getCenter` → `Vec3.atCenterOf`.
- `Item.getName()` needs a stack. `Player.sendOverlayMessage` / `sendSystemMessage`.
- Entity tags: `entityTags()`. `net.minecraft.util.TriState`. `net.minecraft.client.renderer.entity.RenderLayerParent`.
- **Entity type constants** live in `net.minecraft.world.entity.EntityTypes`.

**Packages**
- Projectiles: `projectile.arrow.AbstractArrow`, `projectile.arrow.ThrownTrident`, `projectile.throwableitemprojectile.ThrowableItemProjectile`.
- Mobs: `monster.cubemob.MagmaCube`, `animal.equine.AbstractHorse`.

**Items**
- `Item.Properties`: `.sword(material, damage, speed)`, `.humanoidArmor(ArmorMaterial, ArmorType)`, `.attributes(ItemAttributeModifiers)`.
- `ArmorMaterial` is a record: `(durability, Map defense, enchantability, Holder<SoundEvent>, toughness, knockbackResistance, TagKey repair, ResourceKey<EquipmentAsset>)`.
- Shields: check `DataComponents.BLOCKS_ATTACKS` (`ItemAbilities.SHIELD_BLOCK` is gone).

**Entities**
- `LivingEntity.knockback` takes `(double, double, double, DamageSource, float)`. To shove something, use `push(x, y, z)`.
- Positioning and cleanup: `snapTo(x, y, z, yaw, pitch)`, `clearFire()`, `removeAllEffects()`.
- Teleporting: `player.teleport(new TeleportTransition(level, pos, Vec3.ZERO, yRot, xRot, TeleportTransition.DO_NOTHING))`. To send someone to their spawn: `TeleportTransition.createDefault(player, DO_NOTHING)`.

**Rendering**
- `RenderTypes` (`client.renderer.rendertype`).
- `SubmitNodeCollector.submitModel(model, state, pose, renderType, light, overlay, color, null, outlineColor, null)`.
- The main render target is `minecraft.gameRenderer.mainRenderTarget()`.
- Screenshots: `Screenshot.grab(gameDir, name, target, downscale, callback)`.

**Animations**
- Clips are fetched with `AnimationLoader.INSTANCE.getAnimationHolder(id)`, then `definition.bake(root)` gives a `KeyframeAnimation`.
- `KeyframeAnimation` has `apply(AnimationState, ageInTicks, speed)` and `applyWalk(...)`.
- NeoForge loads animations *before* entity renderers are created.

**GameTests:** `RegisterGameTestsEvent.registerEnvironment/registerTest(id, new FunctionGameTestInstance(ResourceKey<TEST_FUNCTION>, new TestData<>(env, structure, maxTicks, setupTicks, required)))`.

**Data**
- Data maps (`registry/ModDataMaps`) sync to clients and support `#tag` keys. Attachments (`registry/ModAttachments`) declared with `.sync(...)` sync on change.
- **NeoForge ships its own copies of about 394 vanilla recipes.** The mod declares `ordering="AFTER"` on NeoForge so our overrides win. Disable a recipe with `{"neoforge:conditions":[{"type":"neoforge:never"}]}`.
- Global loot modifiers load from `data/<ns>/loot_modifiers/*.json`, with no list file.
- The 26.2 `dimension_type` JSON uses `attributes`, `skybox`, `has_fixed_time` and (optionally) `timelines`.
- **Tags:** with `"replace": false` a tag file appends to the vanilla tag. Never overwrite vanilla tags such as `mineable/pickaxe`.

**Abilities, GUI and misc (found in Phase 6)**
- **Entity-type tags:** `EntityType.is(tag)` is gone. Use `BuiltInRegistries.ENTITY_TYPE.wrapAsHolder(type).is(tag)`.
- **Datapack registries don't reload on `/reload`.** For live-tunable JSON, use a `SimpleJsonResourceReloadListener(codec, FileToIdConverter.registry(key))` added in `AddServerReloadListenersEvent`, and sync it in `OnDatapackSyncEvent`.
- **HUD:** `Options.hideGui` is gone; use `mc.gui.hud.isHidden()`. NeoForge's `mc.gui.hud.leftHeight`/`rightHeight` give the status bar heights.
- **Toasts:** `SystemToast.add(mc.gui.toastManager(), new SystemToast.SystemToastId(ms), title, message)`.
- **GUI drawing:**
  - `blitSprite(RenderPipelines.GUI_TEXTURED, spriteId, x, y, w, h[, argbTint])`; sprites live in `textures/gui/sprites/`.
  - `g.pose()` is a `Matrix3x2fStack` (`pushMatrix`/`translate`/`scale`/`popMatrix`).
  - `g.outline(x, y, w, h, color)`.
- **GUI scale:** `options.guiScale().set(n); mc.resizeGui()`.
- **Default keys in 26.2:** G is Quick Actions, X is Load Toolbar and C is Save Toolbar. R, Z, B, N and J are free.
- **Events and entities:**
  - `LivingDamageEvent.Post` isn't cancellable.
  - `AbstractArrow.setPierceLevel` is private: cancel `ProjectileImpactEvent` to pierce by hand.
  - `ServerPlayer.teleportTo(level, x, y, z, Set.of(), yRot, xRot, true)` syncs the client.
  - `CompoundTag` getters are `getIntOr`, `getFloatOr`, `getCompoundOrEmpty` and so on.
  - `playNotifySound` is gone; play client-side sounds from a payload.

**Menus:** `ContainerData` syncs values as 16-bit shorts. Menu slot positions are final, so responsive screens move `leftPos`/`topPos` instead.
